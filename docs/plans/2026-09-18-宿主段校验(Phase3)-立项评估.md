## 3. 实施方案（Phase 3）

### 3.1 契约侧（先改契约，再改代码）

**改动 1：`config.schema.json` 为两个宿主段补键集**（当前二者仅 `{"type": "object"}`，无 `properties`/`additionalProperties` —— 直接加闭合会**禁止所有键**，故必须先补）

```jsonc
"LlmConfig": {                     // 11 键 = liu2 实际消费面（2026-09-18 键级复核）
  "type": "object",
  "properties": {
    "main_provider": { "type": "string", "minLength": 1 },
    "main_model":    { "type": "string", "minLength": 1 },
    "main_api_key":  { "type": "string" },
    "main_base_url": { "type": ["string", "null"] },
    "max_context_tokens": { "type": "integer", "minimum": 1 },
    "consolidation_provider": { "type": "string" },
    "consolidation_model":    { "type": "string" },
    "consolidation_api_key":  { "type": "string" },
    "consolidation_base_url": { "type": ["string", "null"] },
    "activity_timeout":     { "type": "number", "minimum": 0.1 },
    "stream_total_timeout": { "type": "number", "minimum": 0.1 }
  },
  "additionalProperties": false
},
"StorageConfig": {
  "type": "object",
  "properties": { "sqlite_path": { "type": "string", "minLength": 1 } },
  "additionalProperties": false
}
```
并在 `ConfigFile.properties` 中把 `llm` / `storage` 由 `{"type": "object"}` 改为 `$ref` 上述定义。

**改动 2：`config.spec.md` §1 + C-1 改为三类归属，并补 §4 规则**
- §1：把"**严格校验限 core 段**"改为"严格校验覆盖 **core 段 + 宿主段（`llm`·`storage`·`host_components`）**；扩展段键名由扩展声明面决定，根级 `additionalProperties: true` 放行"
- C-1：补第三类"**宿主段由 core 与外壳校验**（键集由本域 schema 声明，**非扩展可决定**）"
- **§4 需补 4 项（审查发现，现为真空）**：①三类归属；②"宿主段键集由本域 schema 声明、非扩展可决定"；③"**未增删/改名键的校验语义收紧 = 不升 VERSION**，登记 PENDING"；④**宿主段键的增删改归属哪个演进级别**（现无规定，须定：建议与 core 键同规则 —— 增 = minor、删/改名 = major）
- `PENDING.md`：新增一条 errata 登记（涉及域 config），说明 G2 修复、三类归属与上述演进分类

### 3.2 实现侧（零白名单）

- `core/config.py` 新增 `check_declared_segments(cfg) -> None`：遍历 schema 中**已闭合声明**（`additionalProperties: false`）的宿主段（当前 `llm` / `storage` / `host_components`），逐段调 `validate_against_schema` → 失败按既有 `_config_code_for()` 映射为 `CONFIG_*` 码并抛 `ValueError`。
  - 现状复用的 `check_host_components_segment()` 可改为该通用函数的特例（保留其"逐条定位 `host_components[i]`"的可读性输出）。
- 调用点：`create_app` 中 `core_config_from(cfg)` **之后**（core 段仍走手写校验 —— 它承载 schema 未表达的语义，如 `injection_budget_chars` 每层范围；契约同步锁已有测试保证不漂移）。
- **不新增任何键集白名单**：键集改动只改 schema 即生效（延续 Phase 1 架构）。
- **core 段不迁**（同 Phase 1.5 决议）：前置需 `core/schema_check.py` 补 `propertyNames` 支持，且会弱化分层范围校验。本轮不做，已登记。

### 3.3 测试与套件

- `tests_core/test_config.py`：新增 `llm` / `storage` 未知键、必填、类型（含"数字字符串被拒"）各组断言。
- 行为套件：新增 `cases/47-config-host-segment-strict.json`（`llm` 未知键 → `CONFIG_UNKNOWN_KEY`；`storage` 未知键 → 同）。
- **套件成本修正（审查发现，原评估偏乐观）**：`runner.py::_run_config_case`（`:1533-1626`）现仅对 `inputs.valid`/`inputs.invalid` 调 `core_config_from`（`:1547/1557`），**不调用任何宿主段校验**。故新增该用例至少需 runner 改 **2 处**：①该函数内按 item 分派到 `check_declared_segments`；②把新用例 id 加入 `protocol_pipeline_ids`（`:1992-2006`），否则会落入 `_run_pipeline_case` 被误处理。`inputs.invalid` 的 `{label,cfg,code}` 形态**可直接复用**（语义改为宿主段）。→ 成本定性：**中低**，非"低"。
- **变异验证**：①移除 `check_declared_segments` 调用 → 新断言必红；②schema 删一个属性 → 契约同步相关断言必红；③还原逐字节。

## 4. 迁移风险

| 风险 | 评估与对策 |
|---|---|
| 若有人 `TEAGE2_CONFIG` 指向老系统 `config.yaml` | 严格校验会**启动失败**（`context_threshold` 成未知键）——这是**期望的 fail-fast**（"这份配置不属于 liu2"），但须在文档/变更记录明示 |
| 数值键的"数字字符串"被拒 | 属收紧；须在 `PENDING.md` 与开发日志明示，并给出迁移提示（改 YAML 写数字） |
| `config-liu2.yaml` 现状 | **已合规**：Phase 1 键级清理后 `llm` 11 键、`storage` 仅 `sqlite_path`，均为纯数字/占位符 → 预期无需迁移（执行时以实跑复核） |
| 其他段（`a2a`/`cron`/…） | **不受影响**：根级 `additionalProperties: true` 保持（老系统段与未来扩展段照旧放行） |
| 枝干段 `core.branches.<name>` | **不受影响**：仍由扩展 setup 自校验（C-1 不变） |
| **越界键的现存位置（审查已穷举）** | `llm.context_threshold`：`config.yaml:90`、`config2.yaml:82`、`config.yaml.bak:81`、`config.yaml.example:17`；`storage.session_ttl_days`/`cleanup_interval_hours`：`config.yaml:234-235`、`config2.yaml:209-210`、`config.yaml.bak:186-187`、`config.yaml.example:50-51`；老系统测试资产 `tests/performance/config.test.yaml:12/40-41`、`tests/test_config_update.py:58/71-72`。**全部为老系统资产，Phase 2 后 liu2 默认路径不会读到** → 默认不触发启动失败；仅当 `TEAGE2_CONFIG` 显式指向这些文件才失败（属预期 fail-fast）。**liu2 自身配置与测试夹具无越界键**（`config-liu2.yaml:50` 等仅 `sqlite_path`）。 |
